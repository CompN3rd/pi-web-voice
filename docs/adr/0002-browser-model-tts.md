# ADR 0002: English browser-model speech synthesis

## Status and scope

Owner requirement accepted. **Runtime, audio controller, UI and separate TTS acquisition/import/export are implemented.** The browser executes pinned English Whisper and Kokoro `af_heart`; OS synthesis is removed. Automated fake-browser and guarded real-loader evidence exists, but full-model TTS, Pixel and isolated-host acceptance remain **unrun**. Native corresponding-source provenance and combined GPL obligations block release/conveyance; `private: true` is not an exemption. See [qualification](../tts-qualification.md) for exact artifacts and evidence boundaries.

This supersedes permission to use local or network-backed browser/OS voices, including obsolete OS-playback clauses in ADR 0001. It retains ADR 0001's browser-owned acquisition, no-custom-route requirement and compiled asset trust boundary. README/design/security/deployment now describe the model-only implementation, not the retired OS path.

**How to read this ADR:** the numbered sections remain normative delivery requirements, not a claim that all qualification gates passed. The integration map and implementation notes describe current code. Automated checks are recorded separately from unrun full-model/device checks; completion/release remains blocked by the remaining gates.

English only initially. Both speech recognition and synthesis execute on the device running the browser (initial target: Pixel 8). Keep Whisper tiny.en recognition. The implementation replaces OS synthesis with a dedicated TTS worker and Web Audio playback of generated PCM. No Google/Android/system voice, remote speech inference, server-hosted inference, native speech-recognition fallback, or automatic model/voice substitution is allowed. Failure leaves text usable.

This is a complete feature-delivery plan, not an MVP waiver: asset import/export, cancellation, recovery, accessibility, licensing, packaging and real-device gates below are required. It does not add multilingual speech, automatic result narration, voice cloning, conversational routing, wake words, background/locked-screen operation, native applications or worker-control features.

## 1. Candidate, dependency and license qualification

The implemented candidate is **Kokoro-82M through a small direct public-API adapter**, informed by inspected `kokoro-js@1.2.1` but without adding that dependency or its private loaders. It uses one pinned English voice (`af_heart`), fixed normal speed, quantized ONNX weights and single-thread WASM. WebGPU is not a prerequisite or automatic fallback. The phonemizer must also execute locally in the worker.

The inspected artifacts and guarded loader checks establish integration evidence, not a fully qualified model/device/license stack. The repository currently pins Transformers.js `3.8.1` and ONNX Runtime `1.22.0-dev.20250409-89f8206ba4`. The exact phonemizer is `1.2.1`; the adapter configures the Transformers instance bundled into its worker. Both workers use the same pinned version, with one heavyweight runtime resident per document. Preserve evidence of which Transformers/ORT instance receives environment settings. Do not assume a top-level `env` configures a bundled or nested copy. Avoid an unnecessary second runtime; any required upgrade must update matching glue/WASM hashes and rerun recognition runtime/model regression gates, not silently alter Whisper.

Maintain the recorded immutable package versions, model/voice revisions, ordered asset lengths/hashes, transitive executable assets, source provenance and notices. The recorded inventory does not close the native-source/license gates. Test the actual browser bundles, not just TypeScript declarations or upstream examples. If the package lacks a supported injection seam, prefer a small reviewed adapter using public model/tokenizer APIs over hidden package imports, ambient global monkey-patches or an unmaintained vendor copy. Document and license any necessary adapted logic explicitly.

Kokoro's model card declares Apache-2.0 weights; that does **not** establish licensing for its phonemizer/eSpeak-derived runtime, voice data or other dependencies. Audit the complete distributed stack and required notices/source obligations before release. MMS English/VITS is CC-BY-NC-4.0 and is not an approved substitute. Failure of compatibility, licensing or device gates requires a reviewed candidate change, not a weaker privacy boundary.

## 2. Complete loader boundary, including voice data

Do not call upstream `generate()`/`stream()` and assume Transformers' remote-model flag makes everything safe. In the upstream source examined during review:

- Voice data uses a separate `kokoro-voices` Cache Storage cache, reads it without manifest verification, and can fetch `resolve/main/voices/<voice>.bin` on first generation.
- Model/tokenizer creation and voice loading have different configuration paths.
- Phonemization introduces additional executable/runtime dependencies.

All required voice, model, tokenizer, phonemizer, data and runtime bytes must be acquired/verified during explicit preparation. Disable or bypass upstream private cache/load paths; an already populated unverified `kokoro-voices` cache must never be trusted. Map any necessary library loader requests only to exact compiled assets, with no native fetch on misses. Prefer passing verified voice data through the adapter. No mutable `main` source may become a production download URL.

Install network restrictions **before evaluating dependencies that could load assets at module initialization**. ESM static imports run before the importing module's body; merely copying the current worker's import order is not proof of confinement. Inspect emitted bundles and use a guarded bootstrap/lazy import where required. Deny XHR fallback and audit fetch, dynamic imports, WASM loaders and nested workers; no unchecked executable CDN imports or alternate transport bypass. This is a reviewed trusted-code boundary, not a claim that overriding fetch sandboxes arbitrary JavaScript.

Only explicit acquisition receives the native downloader. It uses pinned HTTPS sources, omitted credentials/referrer, bounded decoded bodies, known final distribution hosts and SHA-256 verification. Preserve the documented limitation that browser Fetch does not attest every redirect hop. Never attach task text to download URLs or logs. Cache preparation, import, initialization from verified assets and inference make no distribution-network requests. Missing files fail closed; explicit Download may replace a bad entry once, not retry indefinitely.

## 3. Pack descriptors, bounds and portable compatibility

The original recognition helper accepts only `models/` and `ort/`, hardcodes Whisper/runtime URLs, caps each file at **64,000,000 bytes**, the total at **100,000,000 bytes**, and the count at 20. Those recognition limits and format remain unchanged in the shared helper; TTS now has its own exact path policy and 96,000,000-byte per-file / 128,000,000-byte total / 12-file limits. The pinned inventory contains a **92,361,116-byte model** at revision `1939ad2a8e416c0acfeecc08a694d14ef25f2231`; the complete TTS payload is **115,849,893 bytes**, plus the eight-byte header. This pin/size is not evidence that weights were exercised. Quantization labels do not reliably imply a smaller artifact.

Use separate compiled recognition/TTS pack descriptors with explicit allowed asset kinds, paths, distribution mappings, exact lengths/hashes and finite per-file/count/total limits. Choose TTS limits from its qualified inventory with documented headroom, not arbitrary caller-supplied manifests or unlimited bounds. Keep traversal, duplicate path, origin and safe-integer checks. Account for full-file hash buffers, Response copies, runtime initialization and model tensors when measuring peak RAM; file size is not resident memory size.

Preserve existing Whisper `.pivoice` files and their `PIVOICE1` ordering. For TTS, retain the fixed raw-concatenation format with a **distinct eight-byte magic `PIVOTTS1`**, `.pivoice` extension and dedicated TTS control/CLI pack selection. The magic identifies pack kind, not trust: only the installed compiled TTS descriptor supplies order, bytes, paths and hashes. Wrong kind/version, truncated/oversized or stale packs reject; imports cannot supply executable manifests or paths. New asset revisions require matching exports. Never append TTS assets to the existing Whisper pack implicitly.

Provision/export tooling must explicitly select a known pack, default existing commands to recognition for compatibility, require public-download opt-in, operate outside the package root, reject symlinks as today, verify every source asset and publish exports atomically. Preserve notices/provenance separately from the raw import. No build/install/package hook downloads models.

## 4. Cache identity, recovery and storage ownership

Use distinct versioned recognition and TTS caches keyed by compiled inventory identity, with module-relative synthetic URLs that are never fetched as host routes. Initially keep each pack self-contained, even if runtime bytes are duplicated across caches; disclose actual disk requirements. Do not introduce shared-cache reference counting merely to save that duplication.

Readiness requires every asset verified and the actual pipeline initialized. Partial verified entries may survive cancellation/storage failure and be reused, but cannot publish readiness. Cache put/match failures, quota exhaustion, unavailable Cache Storage and eviction leave a recoverable text-only state. Estimates from the Storage API are advisory; do not require persistence permission or assume a quota check reserves space.

Expose bounded metadata (pack identity, readiness, checked bytes and sanitized failure category) and explicit retry/reimport/download and **clear-this-pack cache** actions. Clear must cancel this page's use of that pack first, delete only plugin-owned exact cache identities, reset readiness and never clear host data/worker ledgers or another pack. Preserve safety latches. Do not automatically prune other revisions that an older tab may use; explicitly selected old-cache cleanup must identify what is removed. Concurrent same-version preparation may write only independently verified bytes; eviction/clear during another tab's load must fail closed. Already verified in-memory weights may continue in another tab; cache removal is not cross-tab cancellation.

## 5. Runtime protocol and controller state

Construct the controller inertly. Unlike an eager worker created from `updated()`, mounting/recreating a panel must not allocate a heavyweight pipeline, acquire assets, resume audio or restore playback permission.

Track structured state separately: unprepared, preparing, ready, synthesizing/playing (which may overlap), stopping, failed and disposed; track explicit playback enablement, audio safety and source identity independently. Never infer authority/readiness from a status string such as `Text only:`. Treat a worker with terminated weights as unprepared even when its disk cache is complete.

The TTS protocol has an explicit version, compiled pack/build identity, one pending operation per worker, monotonically increasing request IDs, a worker-instance epoch, typed prepare/progress/ready/chunk/error responses and bounded messages. Preparation must confirm the expected protocol and pack/build identity so stale served workers cannot publish readiness; mismatches fail with a reload/reprepare instruction, not automatic recovery. Validate expected response kind as well as matching ID. Validate chunk index, sample rate, PCM type/size and operation state on both sides. Reject malformed matching responses; ignore stale responses without changing readiness. Transfer PCM buffers rather than cloning them. Status and error messages must be sanitized codes/bounded metadata, not arbitrary upstream text/phonemes/tensors or signed URLs.

Worker construction, postMessage/transfer, `error`, `messageerror`, preparation, synthesis and timeout failures settle promises exactly once, release timers/listeners/buffers and require explicit recovery. Busy requests reject rather than disappear into a timeout. Cancellation terminates CPU work immediately via worker termination; it must not wait for an inference-blocked message handler. Reject pending callers and fence already queued callbacks before cleanup. Reentrant status callbacks and cancellation before an await is registered must not resurrect operations. Do not retain input text for automatic replay.

## 6. Audio teardown and page-level safety

The retired OS output used synchronous `cancel()/dispose(): boolean`. The implemented Web Audio and capture paths retain asynchronous resume/close settlement under document-level coordination; capture cannot start through an unchecked fire-and-forget teardown. The five-second deadline and unsafe latch apply to capture teardown as well as playback.

Use a page-level audio ownership/safety coordinator shared by panel instances. Safety state must outlive a controller, AudioContext, workspace switch and panel remount; keying a latch only by each new context loses today's protection. Coordinate all plugin capture/playback owners in the same document, not unrelated host audio. Cross-tab microphone/speaker exclusivity is not guaranteed; state that limit and do not claim a tab controls another tab's audio.

On stop: invalidate operation epochs first; terminate synthesis, cancel timers, remove callbacks, discard queued PCM, mute/disconnect the owned output graph and stop all owned sources. Attempt each independent cleanup even if another throws. Track asynchronous close/teardown settlement; while stopping, capture and new playback stay blocked. Use a bounded teardown deadline. If silence cannot be established or teardown remains uncertain, latch an unsafe state that blocks audio preparation, capture and playback across remounts until document reload. A late `ended`, resolved `resume/close` or a replacement wrapper cannot clear it. Text/worker inspection remain usable.

`shutdown()` must invalidate panel/permission epochs immediately without waiting for cleanup, while the page coordinator retains ownership of unfinished teardown. `toggleRecording()` must await safe teardown, then recheck current scope/generation, target/revision, visibility, readiness and approval state before requesting microphone access. Disabled buttons alone are not safety checks. A second click or scope change during that await cannot start capture or replace the pending operation.

## 7. Half-duplex and model residency

Half-duplex means more than not playing while recording: TTS acquisition/loading/synthesis must not compete with microphone startup, recording, transcription or recognition preparation. Start with **one heavyweight speech runtime resident per document**, managed by the page coordinator; do not assume idle Whisper plus Kokoro fits Pixel memory. No simultaneous preparation/download jobs in this page.

Preparing TTS explicitly releases idle recognition resources and marks recognition unprepared; preparing recognition first stops/releases TTS safely and clears TTS readiness. Preserve cached bytes, typed drafts and worker state during this deliberate resource handoff: do not reuse broad panel `shutdown()` just to evict an idle model. If recording/transcribing is active, TTS preparation/playback rejects rather than secretly ending an utterance. Capture can interrupt TTS only after safe stop and recognition is explicitly prepared again. Display which pack needs preparation; do not reload either model automatically behind a Speak/record button.

Successful idle TTS can remain resident until Stop, resource handoff or lifecycle invalidation. **Stop speaking** cancels pending preparation/synthesis/playback and releases TTS resources, requiring explicit preparation again, but does not revoke instruction approvals, clear drafts, stop recognition or cancel coding workers. **Cancel / voice off**, hide, close, context/target/worker-model changes and selected reply-revision invalidation retain existing broader shutdown/revocation semantics and revoke playback enablement. Returning to visibility never resumes automatically. Handle pagehide/bfcache restoration conservatively as well as visibility/unmount.

## 8. User-gesture Web Audio and bounded output

Preparing a pack is silent and does not enable narration. Provide explicit enablement for the named pinned English voice and separate Speak actions. Create/resume the owned playback AudioContext directly from the Speak gesture **before awaiting inference**, not from a later worker callback. Do not route the gesture-dependent step through generic deferred work and assume activation survives. Reject or show a fresh-tap action if autoplay policy denies it; never replay retained text automatically. Recheck job/context identity after every asynchronous resume and before creating/starting sources. Verify the context is actually running; suspension/interruption during playback stops the job rather than scheduling audio that can surprise the user on resume.

Use a separate playback graph, not the microphone capture context. Declare the model's pinned output sample rate (Kokoro candidate: mono 24 kHz); create AudioBuffers at that rate and let Web Audio perform device-rate conversion. Never reuse the recognition 16 kHz constant. Validate finite samples, nonempty duration and amplitude bounds before playback, apply a bounded output gain, and reject malformed output without clipping it into apparently valid results. Release source/buffer references after completion/cancellation. Do not save generated WAVs, use downloadable recordings, persist PCM or cache spoken text.

Initial hard safety ceilings (not performance promises): existing 1,000 UTF-16-code-unit playback prefix; at most 32 text chunks; at most 30 seconds PCM per chunk and 120 seconds total PCM; one playing buffer plus one pending/in-flight chunk; 300-second preparation deadline, 60-second runtime initialization deadline, 120-second synthesis inactivity deadline, 300-second whole playback-job deadline, and 5-second teardown deadline. Enforce on the main thread and worker so a blocked inference cannot disable its own watchdog. Status progress cannot extend absolute deadlines. Derive PCM byte limits from pinned rate/channels. Any ceiling change requires documented review and regression tests; Pixel acceptance can require tighter limits or a different candidate.

Use backpressure: do not synthesize all chunks into an unbounded queue or pre-schedule a long chain of source nodes. A repeated Speak request rejects while busy; it is not queued or replayed. The user may Stop and explicitly prepare/speak again. A failed later chunk stops the remainder and reports partial playback, never success or automatic restart.

## 9. Text fidelity, chunking and source identity

Preserve the current **explicitly labelled prefix playback** contract rather than silently treating the 1,000-character prefix as a full result. The UI retains the complete result/question. Select the prefix without cutting a UTF-16 surrogate pair; show the exact selected text/range. Empty/whitespace-only input rejects. Do not execute markup, follow URLs, interpret instructions in results, summarize with another model or dispatch anything based on spoken content.

Kokoro's examined `generate()` and stream helpers tokenize with `truncation: true`; sentence streaming alone is not a no-loss guarantee for long sentences, URLs or code. The adapter must segment bounded input at sentence/word boundaries where possible, then enforce the **qualified tokenizer's actual token budget including special tokens after phonemization**, without truncation. Split long spans further at safe character boundaries and re-tokenize; terminate on no-progress/unsplittable input or chunk-count overflow. Reject before audio starts if the selected prefix cannot be represented under the limits. Cover numbers, abbreviations, punctuation, emoji, non-English/mixed text and unbroken strings. English-only is a capability limit, not a language-detection guarantee; unsupported text must not trigger another language/model. Keep normalization deterministic and documented, not a semantic rewrite; display limitations for code/identifiers.

Current admission additionally rejects signed numbers/ranges, malformed numeric forms, numeric cores over 15 digits and phonemizer spans over 32 characters. Decimal/grouped-number/time expressions and dotted abbreviations remain atomic through phonemization and chunking. Real pinned dependency probes demonstrated silent truncation of long words/numbers before tokenization; conservative input bounds reject those inputs before eSpeak. Tokenizer fidelity uses single-token public decoding because the pinned null sequence decoder inserts spaces. This is input-retention evidence, not pronunciation or model-audio qualification.

Bind each playback to an immutable snapshot of source text, panel scope/generation and, for a result, worker ID/revision and detail-read sequence. The implementation adds a latest-request ticket alongside scope fencing so an old read cannot overwrite a newer selection or reopen a closed detail. Closing/replacing detail cancels its pending read and playback. A known revision change invalidates playback/detail even when that worker is not the selected reply target. Status narration is a labelled snapshot of captured statuses/revisions, not a live claim; a known change to a narrated worker cancels that snapshot rather than altering a queued chunk. Never automatically re-read or re-speak after a poll/update.

## 10. UI, picker and privacy behavior

Use independent Recognition and Playback sections, each with cached preparation, explicit pinned download, local import, progress, Cancel/Stop and recovery. Display exact descriptor-derived acquisition totals separately; approximately 65 MB describes recognition only. Show cache presence separately from initialized readiness, download size separately from RAM, and resource handoff consequences before the action. Missing TTS must not block text or recognition; missing recognition must not block text or TTS.

Replace `selectedVoice`, OS inventory refresh and browser voice diagnostics with structured TTS state and explicit named-voice enablement. No loading, permission grant or successful preparation causes automatic speech. Reset enablement on full off/hide/context teardown. Disabled controls and handler checks must agree across preparing, stopping and unsafe states; ordinary text editing/approval must not depend on TTS availability. Keep audio operation state distinct from the existing recognition `busy` getter and instruction `approving` state.

Each file picker has its own pack kind and selection ticket, containing scope plus a monotonic invalidation token. Selecting a file performs no import. Android's picker-induced hide may preserve only that ticket for a later visible **Import selected TTS pack** tap, never active audio or permission. Explicit off, target/model/session/workspace changes, unmount or a newer picker must invalidate it even after a scope changes away and back. Same scope-string equality alone is insufficient. Test cancel/no-file, wrong-pack selection and both picker kinds without cross-wiring assets.

Provide labelled controls, keyboard/focus behavior, screen-reader-friendly bounded progress/status updates and explicit error/partial-playback messages at phone viewport sizes. Diagnostics contain only bounded model/runtime/pack state, timing and failure categories—no result text, transcript, phonemes, audio, credentials or signed URLs. Do not forward diagnostics automatically. External downloads disclose metadata; local inference does not make approved Pi worker text private/offline or alter provider costs.

## 11. Packaging and deployment

Bundle the TTS worker/controller and reviewed small executable dependencies under module-relative plugin URLs. Keep large model/runtime/voice assets outside installed roots. Inventory the phonemizer's emitted files and any embedded data/base64 WASM; the existing extension-based payload scanner alone cannot detect embedded payloads. Include all necessary notices/provenance through the package allowlist and test a clean build plus rebuild over prior generated output. Cleanup must remain restricted to known generated files and never delete an operator's external pack.

Run both browser-directory and **whole-package uncompressed-byte** gates. The implemented build is approximately **4.75 MB uncompressed**, including two Transformers worker bundles and excluding external packs; verify the package gate separately for the final artifact. The total installed artifact must remain below 16 MiB, including duplicated worker JavaScript, embedded runtime data, documentation and notices. Do not evade the cap with compressed tarball size, data URLs, symlinks or extra host routes.

Require a full page reload when transitioning from the OS-synthesis build; do not hot-swap controllers and assume legacy page-global speech was stopped. Verify nested plugin paths and authenticated host CSP for worker creation, blob modules and WASM. Import avoids distribution-network restrictions, not execution restrictions. No service worker, proxy mapping, weakened CSP or cross-origin-isolation deployment change is required. If the existing host cannot execute the qualified runtime, fail clearly to text and leave acceptance blocked.

## 12. Verification matrix and delivery gates

The integration checkpoint reports **164 unit/contract + 16 deployment tests** and **129 fake-browser checks** passing, plus prior guarded real phonemizer/ORT loader checks without weights. OS-only assertions have been replaced by model-controller lifecycle expectations; backend admission/companion, recognition and approval suites remain. Real-tokenizer compatibility has regression coverage. These checks are not full-model TTS, intelligibility or device acceptance, and do not certify every item below as completed.

1. **Assets/tooling:** descriptor bounds and path/source rejection; wrong-kind/version/header/order/size/hash; corrupt cache repair only on explicit download; quota/cache failures; partial cancellation; concurrent preparation/clear/eviction; preserved Whisper export/import; symlink-safe atomic TTS export; package notices and complete size inventory. Exercise per-file corruption including voice and phonemizer bytes, not only ONNX weights.
2. **Controller/protocol:** strict message kinds/IDs/epochs, wrong-rate/non-finite/oversized PCM, chunk order and backpressure, repeated clicks, worker constructor/postMessage/error/messageerror failures, all deadlines, synchronous callback reentrancy, stale progress/results, partial playback and deterministic cleanup. No automatic retry, download or text replay.
3. **Real-controller fake-browser matrix:** cancel at acquisition, initialization, resume, synthesis, queued/playing audio and teardown boundaries via Stop/off, hide/pagehide, context/session/target/model/revision change, detail close/replacement and unmount/remount. Include pending resume/close that rejects, never settles or resolves late; source stop/disconnect failure; unsafe latch persistence and direct handler calls despite disabled controls; two same-document panel owners; capture attempts during teardown. Verify all owned tracks/sources/workers are released and late callbacks cannot revive them. Test explicit enablement, no automatic playback, picker hide/ABA, token-safe long input, partial-output UI, accessibility and exact text approvals/unknown outcomes.
4. **Network regression:** make access to OS speech APIs fail the test. Instrument networking from worker bootstrap onward, including module initialization and first voice/phonemizer use. Seed a poisoned upstream `kokoro-voices` cache; it must never supply unchecked voice data. Deny native XHR and unexpected fetch/import/nested-worker requests. Blocking a request is not evidence of zero attempted requests; assert both. Test cache/import inference under restrictive CSP with no speech-serving route and no model downloads.
5. **Actual runtime:** retain the current ORT eviction/corruption test and add TTS/phonemizer loader equivalents. Do not substitute away the loader whose safety is under test. Check verified executable/WASM bytes and no fallback on missing/corrupt files, including after initial verification. Default tests require no model weights, public download or paid inference.
6. **Actual model:** a separately invoked test uses an operator-provided, externally stored verified TTS pack and the production worker/adapter. Generate finite, bounded, nonempty PCM with the pinned rate, using short text and multi-chunk/long-token cases; verify voice loading, cancellation/reprepare and zero inference network attempts. Repeat recognition model tests if shared code/runtime changes. Weight provisioning and direct-download CORS tests require explicit opt-in; never scan credentials or silently fetch weights to make tests pass. Desktop PCM smoke is not intelligibility or phone-performance acceptance.
7. **Commands:** during implementation run `npm run verify`, `npm run test:browser`, `npm run test:runtime`, `npm run check:package` plus `node test/tts-runtime-browser.mjs` with explicit `VOICE_TTS_PHONEMIZER_FILE`, and `node test/tts-model-browser.mjs` with explicit `VOICE_TTS_PACK_FILE`. The latter remains unrun; neither implicitly downloads assets. Use installed Chromium/Edge; no browser auto-install. Record exact commands, versions, artifact byte counts and evidence boundaries. A plan-only review must not run build-producing commands or claim new runtime validation.
8. **Pixel/isolated host:** after separately authorized acceptance, verify real authenticated plugin URLs/CSP, direct download and file import, cold/warm startup, first-audio latency, sustained synthesis rate, intelligibility across prose/numbers/code, peak memory/repeated runtime handoffs, heat/battery, storage pressure, background/lock/bfcache, Bluetooth/headsets, audio interruption and stop latency. Test cached offline speech while distinguishing the online shell/workers. Confirm silence and released microphone indicators after every cancel path. Define owner-approved latency/memory/thermal acceptance thresholds before this window; collect measurements and reject the candidate if they fail rather than declaring eventual audio sufficient.

Completion requires qualified pins/inventory/licenses, all automated gates, updated README/design/security/deployment guidance, preserved historical validation records clearly labelled as superseded, and separately recorded live-host/device evidence plus owner release approval. Specifically retire network-voice permission and OS-airplane-mode guidance from current documentation; retain useful historical records without presenting them as Kokoro acceptance. Do not mark missing real-device or license gates as waived because the package is private.

No activation, installation, paid inference, publication, push or live-daemon restart is authorized by this plan or its review. Default package remains private and disabled. Any authorized daemon restart must be arranged outside hosted sessions and warn that it interrupts active work.
